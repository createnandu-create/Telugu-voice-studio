# v0.8.0 — workspace isolation, mixed-script narration and experimental local tone conversion

This is an ARM64 Android test build. Nothing Phone (1) installation, first-tap listening, speaker similarity, thermal behavior and 10–20 minute cloned narration still require physical-device acceptance. The supplied user recording is not included in this public evidence folder.

## Implemented behavior

- A new Studio ViewModel starts at Script with no restored `last-result.txt` audio. Completed Projects and original scripts remain on disk. Voice changes stop/release app playback, clear the active result, cancel an older render, and queue one new render when the selected installed model and script are ready. Run IDs and workspace revisions reject stale results and pending requests. A screen rotation keeps its existing ViewModel.
- Piper and Tiny sessions are constructed and closed per render. PCM cache receipts now also require the correct model-native rate: Piper 22,050 Hz; Tiny 24,000 Hz. There is no shared AudioTrack object in this app; playback uses MediaPlayer. The reported hardware/JNI cause was **not reproduced or established**.
- Both native rates now master to 44,100 Hz stereo through sinc interpolation. Mastering starts with exactly 150 ms of zero PCM, adds a 15 ms linear onset fade, appends 100 ms of zero PCM and measures gated loudness / 4× reconstructed peak. These guards cannot recreate a phoneme absent from synthesis. Raw output remains available, unaltered and at its native rate.
- Default delivery switches: YouTuber, duration guard, question endings, comma buffer and careful diction ON; female EQ and warmth EQ OFF. Piper fixed-voice output bypasses waveform pitch/time alteration. Rate and pause controls remain available. The question/waveform DSP operates on Tiny or converted voices; it is not a learned semantic speech director.
- Speech-only normalization runs before tokenization: user dictionary, cardinal/math normalization, markup cleanup, CMU English phonemes mapped to Telugu and letter-name fallback for unknown English. Original editor text and saved plans stay unchanged. Supported examples include AiTechApp, PixelLab, 100%, √25, `\sqrt{25}`, 16:9, 4K and 192-D. Unknown words may be spelled, not naturally pronounced; arbitrary mathematics and all model pronunciation defects are not solved. Telugu conjuncts are preserved; no fabricated phoneme IDs or weight changes are introduced.
- Persisted voice/date/time stems are shared by Projects and device export suggestions. Existing custom project names remain unchanged. Android storage providers may disambiguate colliding names. English month names and 12-hour AM/PM use the device's local time zone.
- Projects use top-aligned, compact animated rows, marquee titles and five 48 dp action targets. Delivery uses toggle pills; export has a fixed Review / Open Saved Folder row. SAF destinations open the system folder browser at the last saved document; one-tap Downloads exports open Downloads.
- Enhance updates one recording card and increments Cleaned (1x/2x), while retaining the source and earlier private audio files. Processing always starts from the retained original/capture. RNNoise cleanup adds an optional WPE stage and a +2.5 dB / 3.5 kHz presence shelf with peak protection. WPE reduces some room tails; **0% reverb and recovery from arbitrary wind/clipping are impossible guarantees**.

## Real OpenVoice V2 path, with a device-generated preview gate

Settings → Voice cloning → Download OpenVoice (41.1 MiB), then Voices → Create voice preview. Explicit speaker consent and at least 10 seconds of clear reference audio are required. A cleaned 10–15 second reference feeds the actual OpenVoice reference encoder. A local tone conversion must produce a valid preview WAV before the profile appears as an **experimental Cloned** narrator. Recording or ECAPA enrollment alone never enables that tile. Editing/enhancing the reference invalidates its older clone preview until regenerated.

Base Telugu narration is generated by the selected existing Piper/Tiny model. The base model is released before OpenVoice conversion; converted sentence chunks are checksum-cached, joined and mastered locally. Optional pitch contours run after conversion. No inference server or API key is used. The model downloader alone uses the network.

OpenVoice's `gin_channels` and encoder output are **256 dimensions**, unlike the separate ECAPA 192-D fingerprint. Injecting that unrelated 192-D vector into fixed-speaker Piper would be invalid. No such injection occurs. The conversion model already contains its waveform decoder; this build does not pretend to replace it with an unrelated vocoder.

Pinned community ONNX export: `Q-P1NG/openvoice-v2-onnx@9383bf8b636a05319f94a4bb181777f32f6f8dfd` (MIT). Its upstream export provenance is bundled separately and is an upstream statement, not a benchmark performed here.

Encoder input `[1,time,513]`, output `[1,256]`. Converter inputs: magnitude spectrum `[1,513,time]`, int64 lengths, source/target embeddings `[1,256,1]`. Frontend: 22.05 kHz, periodic Hann 1024, hop256, reflect pad384, magnitude epsilon1e-6. The Java path pads to complete final hops and trims output to the original duration.

**Verified host evidence:** `OpenVoice-public-tone-conversion.wav` is an actual 5-second Telugu conversion from public pretrained Venkatesh speech toward a public Padmavathi reference. Java encoder + converter took 8.354 seconds on this Linux host, produced 110,250 finite PCM frames. This is not the user's personal voice, a phone benchmark, a similarity score, or proof of intelligibility. On-device use is experimental until listened to on the target phone.

## Four fresh mixed-script fixtures

`script.txt` contains the exact original and spoken inputs. Raw WAVs are first inference calls in newly constructed engines: two Piper voices at 22.05 kHz and two Tiny voices at 24 kHz. Tiny uses its duration guard, seed42 and neutral speed1. Piper uses neutral speed1 and the existing pinned start-token input adapters. These isolate text normalization and signal mastering; they are not recordings of the full Android auto-direction flow. No new voice training occurred.

All raw and mastered files have SHA-256 and PCM metadata in `audio-manifest.json`. Resampling does not recover higher-frequency detail missing from the original. Raw/master comparison is essential before accepting perceived clarity.

## Reproduction and acceptance

Run `scripts/test-java.sh`, `scripts/test-restoration.sh`, `scripts/test-android-regex.py`, `scripts/verify-bundle.py`, then Gradle `:app:assembleDebug :app:assembleFresh :app:testDebugUnitTest :app:lintDebug` under `offline-tts-android` with JDK17 and Gradle8.9. Host helpers in this directory require the pinned models, ONNX Runtime Java and the RNNoise host library; they generate only public comparison speech.

Regression tests cover the exact English/math cases, retained original script, clone vector shape rejection, stable timestamp names, cold workspace / voice-switch playback reset, wrong-rate cached audio rejection, 22.05→24→22.05 mastering state independence, head/tail PCM padding, loudness/peak, consent gating and compact 360 dp Projects actions. AAPT normally strips `.gz` extensions, so the compressed dictionary is deliberately shipped as `.bin`; a packaged-asset test loads it through Android AssetManager.

Physical-phone acceptance still needed: update the same package without uninstalling, install models once, airplane mode, cold launch, switch all four voices, listen to the very first generated “నమస్కారం” and mixed-script paragraph, test cancellation/restart, then create an owned-voice preview and a 10–20 minute cloned narration. Check memory, heat, speed, pronunciation and similarity. No LLM semantic director or universal zero-echo restoration is included.
